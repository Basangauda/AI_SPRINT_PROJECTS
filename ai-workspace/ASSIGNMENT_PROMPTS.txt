Technical Requirements – Greenfield Quiz Maker Application

This is part of our greenfield Quiz Maker application. The goal of this piece is to allow multiple teachers to collaborate and create a test bank consisting primarily of multiple-choice questions.

Since the application will be used by multiple teachers and users, users need to be able to register, log in, and log out. For the first stage, we will focus only on this functionality and will not implement the MCQ functionality yet.

User Management

We will need a User table in the database. The table should contain:

Primary key / user ID
First name
Last name
Username
Email address
Group
Password

The password must be stored securely by hashing it before saving it to the database.

On the frontend, which will be built later, when comparing a password during authentication, the password entered by the user will need to be hashed and compared with the stored hashed password.

During registration and login, the user's credentials will be sent over HTTP using POST requests.

Database

The database tables required for user management need to be created through a database migration.

User Service

We will need a UserService that provides the base functionality for managing users.

The service should provide methods to:

Create users
Update users
Delete users
Read user information

The UserService will be backed by the database and will provide access to read and write user information.

Endpoints

We will need endpoints for:

Register
Login
Logout

We will also need readable views for the user-related functionality.

Authentication Scope

At this stage, we will keep authentication simple.

We will not implement:

Social logins
Tokens
Session management
Cookies
Any other session-management capabilities

This is intentionally a simple implementation to get the application started.

Post-Login / Registration Flow

When a user successfully logs in or registers, they should be taken to a stub page for the MCQ functionality.

The MCQ functionality itself will be built in the next sprint. That future work will cover creating and managing the questions.

For this stage, we do not need to implement any of that functionality.

This is the baseline requirement for the first stage.
